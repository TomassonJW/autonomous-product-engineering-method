# Standard premium

Premium est le standard opérationnel de la méthode.

Il ne signifie pas cher, brillant, animé ou maximal. Il signifie que le produit se comporte d'une manière qui mérite la confiance de l'utilisateur.

## Définition

Premium signifie :

- l'action principale est immédiatement compréhensible ;
- le statut du système est vrai ;
- l'incertitude est visible ;
- les réglages par défaut sont de haute qualité ;
- le contrôle avancé existe sans polluer le premier écran ;
- les erreurs expliquent ce qui s'est passé et ce qui peut être fait ;
- les coûts sont visibles ou au moins qualifiés ;
- les actions risquées sont protégées ;
- les parcours utilisateur sont testables de bout en bout ;
- le produit évite les mauvaises surprises.

## Le standard des deux mondes

La méthode vise une synthèse :

- **clarté à la Apple** : cohérence, fluidité, faible charge cognitive, UX soignée, action primaire évidente ;
- **profondeur à la Windows** : configuration, ouverture, inspectabilité, contrôle utilisateur, réglages avancés et workflows experts.

Le but n'est ni l'élégance fermée ni la puissance chaotique. Le but est simple d'abord, profond quand c'est utile.

## Échecs premium

Un produit n'est pas premium si :

- il a l'air raffiné mais ne peut pas terminer un vrai parcours ;
- il cache les coûts jusqu'après l'action ;
- il présente des données simulées comme réelles ;
- il utilise "done" alors que les gates n'ont pas réussi ;
- il force les utilisateurs finaux à comprendre logs ou pipelines ;
- il enterre l'action principale sous la configuration ;
- il ne donne aux experts aucun moyen d'inspecter ou contrôler le comportement ;
- il crée des changements irréversibles sans approbation.

## Checklist premium

À utiliser avant de dire qu'une tranche produit est premium :

- Un débutant peut-il identifier rapidement l'action primaire ?
- Un expert peut-il inspecter ce qui s'est passé ?
- Les données mockées, inférées, inconnues et réelles sont-elles clairement distinguées ?
- Le parcours central est-il testé de bout en bout ?
- Les implications de coût et de ressources sont-elles comprises ?
- Les actions rouges sont-elles bloquées par approbation ?
- Les contrôles avancés sont-ils disponibles sans surcharger le chemin par défaut ?
- L'UI révèle-t-elle la vérité au lieu de jouer la confiance ?

## Exigence de preuve

Ne pas appeler quelque chose premium parce que l'intention est premium. L'appeler premium seulement avec des preuves : parcours testés, UI claire, comportement fiable, statut vrai et limites connues.
