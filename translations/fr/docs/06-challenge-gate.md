# Gate de challenge

Le gate de challenge évite l'exécution superficielle, le faux scope, les coûts cachés et l'autonomie dangereuse.

Ce n'est pas un rituel de permission. C'est une pause structurée avant un travail conséquent.

## Quand l'utiliser

Utiliser le gate de challenge quand une demande implique :

- un nouveau produit ou une capacité majeure ;
- une intention vague mais ambitieuse ;
- des changements d'architecture ;
- des effets externes ;
- une publication publique ;
- des modèles coûteux ou des runs répétés ;
- des données utilisateur ou secrets ;
- de l'infrastructure de production ;
- une affirmation de "premium", "autonome" ou "terminé".

## Ce qu'il faut challenger

Le gate doit couvrir :

- écart d'ambition ;
- ambiguïté de scope ;
- risque UX ;
- risque technique ;
- risque de coût ;
- risque d'autonomie ;
- risque de sécurité ;
- risque de maintenance ;
- risque de passage à l'échelle ;
- mauvaise compréhension utilisateur ;
- alternatives ;
- limites de chaque solution.

## Niveaux de challenge

Utiliser un niveau adapté au risque :

- **Léger** : petite correction locale à faible risque.
- **Moyen** : nouveau workflow, écran ou comportement.
- **Structuré** : nouvelle capacité, fonctionnalité publique ou abstraction partagée.
- **Strict** : effets externes, actions destructives, production, secrets, argent ou publication.

## Forme du rapport

Un bon rapport de challenge inclut :

1. Ce que je pense que vous voulez.
2. Où cela peut être sous-spécifié.
3. Ce qui peut mal se passer.
4. Options et arbitrages.
5. Scope recommandé.
6. Ce que je ne ferai pas sans approbation.
7. Gates d'acceptation.

## Règle de langage clair

Le challenge doit être compréhensible par la personne qui a exprimé l'idée. Utiliser les termes techniques seulement quand ils sont nécessaires, et expliquer leur conséquence.

## Modes d'échec

Le gate de challenge échoue s'il :

- bloque du petit travail avec un processus lourd ;
- se cache derrière des risques vagues ;
- évite de recommander ;
- pose trop de questions à faible valeur ;
- ignore le coût ;
- ignore l'expérience utilisateur ;
- laisse des actions rouges avancer sans approbation.
