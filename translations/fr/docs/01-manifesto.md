# Manifeste

Le logiciel construit avec des agents autonomes ne doit pas devenir du non-sens produit généré plus vite.

Le but n'est pas de produire plus d'écrans, plus de fichiers, plus de routes, plus de tâches ou plus de résumés confiants. Le but est de transformer une intention humaine en logiciel utile, sûr, maintenable, avec des arbitrages visibles.

## L'utilisateur peut parler normalement

L'utilisateur ne devrait pas avoir à dire :

> "Crée un système agentique modulaire, event-driven, gouverné par les coûts, à double plan d'interface, observable et avec autonomie bornée."

Il peut dire :

> "Je veux que le système fasse tout le travail, pas une version jouet."

La méthode existe pour traduire la deuxième phrase en structure d'ingénierie exploitable, sans perdre l'ambition réelle de l'utilisateur.

## Challenger, c'est protéger

Un agent qui obéit seulement peut construire rapidement la mauvaise chose.

Le challenge n'est pas une obstruction. C'est une protection contre :

- le faux scope ;
- les coûts cachés ;
- la fausse UX premium ;
- les démos superficielles ;
- l'autonomie dangereuse ;
- l'architecture impossible à tester ;
- les affirmations publiques sans preuve.

## Premium est comportemental

Premium n'est pas une couche visuelle. C'est le comportement d'un système qui respecte l'attention, la confiance, l'argent, les données et le temps de l'utilisateur.

Un système premium :

- dit la vérité ;
- rend l'action principale évidente ;
- cache la complexité jusqu'à ce qu'elle soit utile ;
- expose assez de contrôle aux utilisateurs avancés ;
- échoue clairement ;
- évite les coûts surprenants ;
- préserve la réversibilité quand c'est possible ;
- mérite la confiance par la preuve.

## L'autonomie exige une gouvernance

Un worker autonome sans limites n'est pas une capacité produit. C'est un processus non maîtrisé.

Chaque worker a besoin :

- d'une mission ;
- d'une queue ;
- d'une limite ;
- d'un budget ;
- de checkpoints ;
- de logs ;
- d'un statut vrai ;
- de conditions d'arrêt ;
- de gates qualité ;
- d'un rapport final qui peut être rejeté.

## Objectif

L'objectif est une méthode réutilisable qui aide humains et agents à construire le bon niveau de profondeur :

- pas un petit outil quand l'ambition est une plateforme ;
- pas une plateforme massive quand le besoin est une action simple ;
- pas une jolie coquille sans parcours fonctionnel ;
- pas un système puissant que seuls les experts peuvent supporter.
