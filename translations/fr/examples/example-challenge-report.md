# Exemple de rapport de challenge

## Demande

> Construire un logiciel qui génère des jeux 3D.

## Ce que cela peut vouloir dire

- générateur de démo ;
- outil de prototype jouable ;
- éditeur de niveaux ;
- pipeline d'assets ;
- extension de moteur de jeu ;
- studio de jeu autonome ;
- operating system complet de production de jeux.

## Niveau de challenge

Structuré.

La phrase couvre plusieurs niveaux d'ambition.

## Risques principaux

- Construire un petit jouet 3D alors que l'utilisateur attend un pipeline de production.
- Commencer l'architecture avant de décider s'il s'agit d'un outil, d'un moteur, d'un studio ou d'une plateforme.
- Cacher les coûts d'assets, physique, tests et performance.
- Concevoir une seule UI qui mélange workflows joueur, créateur et opérateur.

## Scope recommandé

Commencer par un profileur produit et une tranche générateur de prototype :

1. L'utilisateur décrit l'idée de jeu.
2. Le système crée un brief de concept de jeu.
3. Le système mappe assets, mécaniques, niveaux et risques requis.
4. Le système génère un plan de petit prototype jouable, pas un moteur complet.

## Ce qui ne doit pas arriver sans approbation

- affirmer la génération complète de jeux ;
- publier des jeux générés ;
- acheter des assets ou services API ;
- utiliser du contenu protégé par copyright ;
- lancer des boucles de génération non bornées.
